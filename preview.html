1) SRS ฉบับย่อ docs/01-srs.md

หน้าหลัก 3 หน้า

หน้าทำอะไรบ้าง
1. หน้าเลือกเมนูแสดงรายการกาแฟพร้อมราคา เลือกเมนู ความหวาน จำนวนแก้ว กด "ใส่ตะกร้า"
2. หน้าตะกร้าสินค้าสรุปรายการ แก้ไขจำนวนแก้ว (ปุ่ม + / -) แสดงยอดรวม กด "ไปหน้าจัดส่ง"
3. หน้ากรอกเบอร์/ที่อยู่กรอกชื่อ เบอร์โทร ที่อยู่จัดส่ง กด "ยืนยันสั่งซื้อ" แล้วได้หมายเลขคำสั่งซื้อ

กฎเกณฑ์ระบบ (Business Rules)

รหัสกฎรายละเอียด
BR-01ขั้นต่ำ 100 บาทยอดต่ำกว่า 100 บาท → แจ้งเตือน ไม่ให้สั่งซื้อ (เท่ากับ 100 ผ่านได้)
BR-02เบอร์โทร 10 หลักตัวเลข 0-9 เท่านั้น ขึ้นต้น 0 ห้ามตัวหนังสือ/สัญลักษณ์
BR-03ความหวานเริ่มต้นไม่เลือกความหวาน → ตั้งเป็น "หวานปกติ 100%" อัตโนมัติ
BR-04จำนวนขั้นต่ำ 1 แก้วห้ามใส่ 0 หรือติดลบ ทั้งตอนเลือกเมนูและในตะกร้า

3) Postman และ SQL docs/03-postman-sql.md postman/*.json sql/*.sql

Postman — ตั้งค่า Request

Method: POST  |  URL: https://api.coffeeshop.com/orders  |  Body (raw/JSON):

{
  "customer_name": "สมชาย ใจดี",
  "phone": "0812345678",
  "address": "บ้านเลขที่ 10",
  "items": [
    { "menu_id": "M02", "menu_name": "ลาเต้", "price": 45, "qty": 3, "sweetness": "100%" }
  ],
  "total_amount": 135
}

Postman — โค้ดในแท็บ Tests (ตรวจ status 200)

pm.test("Status code is 200", function () {
    pm.response.to.have.status(200);
});

อ่านทีละบรรทัด:
• pm.test("Status code is 200", ...) — สร้างการตรวจสอบชื่อ "Status code is 200"
• function () { ... } — ส่วนที่เขียนว่าจะตรวจอะไร
• pm.response.to.have.status(200); — คำตอบจากระบบต้องมีสถานะ 200 (สำเร็จ) ถ้าไม่ใช่ขึ้น FAIL แดง

ในโฟลเดอร์ postman/ มีไฟล์ Collection พร้อมนำเข้า (Import → เลือกไฟล์ → Send → ดู Test Results) มี 2 request: เคสสำเร็จ (200) และเคสเบอร์ผิด (ต้องไม่ใช่ 200)

SQL — ตรวจตาราง orders

คำสั่งที่ 1: ดูคำสั่งซื้อทั้งหมดคร่าวๆ

SELECT * FROM orders;   -- ดูทุกคอลัมน์ จากตาราง orders

คำสั่งที่ 2: ตรวจชื่อ เบอร์ ยอดเงิน ว่าบันทึกถูกไหม

SELECT customer_name, phone, total_amount  -- ดู 3 คอลัมน์นี้
FROM orders                                 -- จากตาราง orders
WHERE order_id = 1;                         -- เฉพาะคำสั่งซื้อหมายเลข 1

คำสั่งที่ 3: หาเบอร์ผิดรูปแบบที่หลุดเข้ามา (ผลที่ดี = 0 แถว)

SELECT order_id, phone
FROM orders
WHERE phone NOT LIKE '0_________';  -- เบอร์ที่ไม่ตรงรูปแบบ 0 + อีก 9 ตัว

โบนัสในไฟล์ sql/verify-orders.sql: มีคำสั่งที่ 4 หาคำสั่งซื้อที่ยอดต่ำกว่า 100 บาท (ต้องได้ 0 แถวเช่นกัน)

4) Bug Report 2 ข้อ docs/04-bug-reports.md

Bug ที่ 1 Severity: High

ชื่อบั๊ก: กรอกเบอร์โทรเป็นตัวหนังสือภาษาไทยได้ ระบบไม่แจ้งเตือน และสั่งซื้อสำเร็จ

ขั้นตอน (Steps):

  1. เข้าหน้าเลือกเมนู สั่งลาเต้ 3 แก้ว (135 บาท)
  2. ไปหน้ากรอกเบอร์โทร/ที่อยู่จัดส่ง
  3. กรอกชื่อ "สมชาย" เบอร์ "๐๘๑๒๓๔๕๖๗๘" (เลขไทย) และที่อยู่ครบ
  4. กดปุ่มยืนยันสั่งซื้อ

ผลจริง (Actual): สั่งซื้อสำเร็จ ไม่มีแจ้งเตือน เบอร์ถูกบันทึกลงคำสั่งซื้อ ร้านติดต่อลูกค้าไม่ได้
ที่ควรจะเป็น (Expected): แจ้งเตือน "เบอร์โทรต้องเป็นตัวเลข 0-9 ครบ 10 หลัก" และไม่ให้ยืนยันจนกว่าจะกรอกถูก

Bug ที่ 2 Severity: Critical

ชื่อบั๊ก: กดลดจำนวนแก้วเหลือ 0 ระบบคิดเงินยอดติดลบ และสั่งซื้อได้

ขั้นตอน (Steps):

  1. ใส่ลาเต้ 1 แก้ว (45 บาท) ลงตะกร้า
  2. กดปุ่มลด (-) 1 ครั้ง จำนวนเหลือ 0
  3. กดลดอีก 1 ครั้ง จำนวนเป็น -1 ยอดรวมแสดง -45 บาท
  4. ไปหน้าจัดส่ง กรอกครบ กดยืนยันสั่งซื้อ

ผลจริง (Actual): ยอดรวม -45 บาท และยืนยันสั่งซื้อสำเร็จ (หลุดเงื่อนไขขั้นต่ำ 100 เพราะยอดติดลบ)
ที่ควรจะเป็น (Expected): ห้ามลดต่ำกว่า 1 แก้ว กดลบที่ 1 แก้วให้ถามยืนยันลบรายการ และยอดต้องไม่ติดลบเด็ดขาด
